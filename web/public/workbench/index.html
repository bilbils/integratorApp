The architecture, by plane

The load-bearing ruling of 2026-08-08: the Integrator is a control plane, not a database. Control is always the Integrator's. Data is per connector — pass-through, land-in-consumer (the default), or pooled. Compute is either. The bands below are that ruling; a node's position is a claim about which plane owns it. Click any node to see what it connects to and how it was verified.

Capabilities, and the rows each one buys

The rule: everything variable is a row, everything invariant is code. A capability is what makes a row possible. When a requirement can't be expressed as a row, the platform is missing a capability — and the pressure is always to build the special case instead. Each missing capability below names the special case it invites.

Every integration — the rules, the issue, the plan

One row per thing that connects to something outside. Rules are what governs it and is not negotiable. Issue is the single thing standing in the way today. Plan is the order to do it in.
